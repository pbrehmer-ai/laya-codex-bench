# Benchmark findings — 2026-09-22

## Executive result

The corrected Laya-first architecture produced meaningful Codex savings. A development-calibrated cascade over 40 public test cases avoided 42.5% of Codex calls and 42.6% of Codex tokens. Observed accuracy was 80.0%, compared with 75.0% for direct Codex; the paired bootstrap 95% interval for the accuracy delta was 0.0 to 12.5 percentage points.

Mean latency fell 34.2% (4,893 to 3,221 ms) and aggregate median latency fell 13.4%. Mean paired speedup was 4.875x, but paired median speedup was 0.954x: accepted cases are dramatically faster, while the majority fallback cases pay a small routing penalty.

This is a pilot result, not evidence that Laya is generally more accurate than Codex.

AG News saved 85.0% of tokens and calls. Prompt Injections saved 0% because no development threshold met the 95% target; the policy therefore fell back safely on every held-out test case.

| Filter | Token savings | Selection recall | Downstream Codex F1 | Median full / assisted latency |
|---|---:|---:|---:|---:|
| Serial, 800-character file evidence | 22.7% | 100.0% | 1.000 / 1.000 | 9,746 / 34,524 ms |

| One 21-question symbol batch | 61.3% | 66.7% | 0.933 / 0.667 | 8,942 / 48,060 ms |

The conservative filter preserved quality but did not improve latency on this four-core CPU. The aggressive filters reproduced large token reductions but dropped relevant evidence. They are reported as failed quality ablations, not wins.

## Persistent service and resources

Every valid new benchmark used the same process, PID `24284`, without model reloads. The three-checkpoint bake-off cold load took 90.96 seconds.

Keeping all three checkpoints resident caused severe Windows memory commitment and paging:

- private committed memory after the complete suite: approximately 49.8 GB;
- observed working set during the post-suite sample: approximately 0.95–1.43 GB because much of the process had been paged out;
- idle CPU: 0%;
- post-paging inference ranged from 1.37 to 3.41 seconds for the supplied 1/4/12-question probes.

This configuration is useful for checkpoint selection but inappropriate as the normal always-on service on a 31.78 GB machine. The normal service now preloads only `multilingual`; the benchmark helper explicitly preloads all three.

The freshly measured recommended single-checkpoint service adds 1,933.53 MB private memory and 1,626.79 MB working set over the lazy Python process, uses 0% CPU while idle, and completed the 1/4/12-question probes in 112/532/2,408 ms. During those probes the Laya process used 71.5%/59.9%/51.5% of total eight-logical-processor capacity. See the [resource report](resource-usage-2026-09-22.md) for the measurement method and peak memory.

## Interpretation

The large savings come from skipping Codex, not from asking Codex to call Laya mid-turn. Confidence gating also matters: the held-out security suite produced no qualifying local threshold and therefore no claimed savings. Repository filtering can save even more context, but its false-negative risk must be controlled before it is useful.
